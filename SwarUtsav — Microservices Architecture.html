01

Overview

SwarUtsav's SRS already separates the system into authentication, interview orchestration, AI processing, audio/video analysis, scoring, reporting and storage — described as a service-oriented, serverless-first architecture on FastAPI, AWS Lambda, S3, DynamoDB and CloudWatch.

This document translates that SRS into a concrete microservices architecture, organized as eight core services so the project stays implementable, debuggable and deployable within an academic scope while keeping clear separation of concerns.

ASR

Whisper converts spoken answers to transcript text.

Reasoning

Llama 3 via Ollama drives question generation and answer evaluation.

Signal

Librosa / PyAudioAnalysis extract vocal delivery metrics.

Vision

OpenCV + MediaPipe extract observable behavioural indicators.

04

Profile Service

Owns the student's profile independently of authentication — personal information, education, CGPA, technical and soft skills, target job role, experience, and resume upload.

MethodEndpoint
GET / PUT/api/v1/profile
POST/api/v1/profile/resume
DELETE/api/v1/profile/resume

Storage: DynamoDB → UserProfiles · S3 → resumes (PDF, 5 MB limit)

05

Interview Service

The interview manager: creates and configures interviews, starts/stops sessions, tracks question progress, duration and status.

{
  "interviewId": "INT-10291",
  "type": "Technical",
  "role": "Java Developer",
  "difficulty": "Intermediate",
  "duration": 15,
  "questions": 10,
  "status": "IN_PROGRESS"
}
MethodEndpoint
POST/api/v1/interviews
GET/api/v1/interviews · /{id}
POST/api/v1/interviews/{id}/start · /end
06

Question / AI Interviewer Service

Kept separate from the Interview Service. Its job: decide what to ask next — static bank, dynamic generation, role- and difficulty-based, contextual follow-ups.

Example — Candidate: "Java is an object-oriented programming language..." → AI: "What is the difference between method overloading and method overriding in Java?"
MethodEndpoint
POST/api/v1/questions/generate · /follow-up
GET / POST / PUT / DELETE/api/v1/questions

Model: Ollama → Llama 3

07

Speech-to-Text Service

Independent AI processing service. Preferred async path:

S3 Upload → S3 Event → Lambda / Worker → Whisper → Transcript
{ "responseId": "RES-123", "transcript": "Java is an object oriented..." }

POST /api/v1/speech/transcribe

08

Audio Analysis Service

Whisper answers what was said; this service answers how it was said — speech rate, pitch and variation, pause duration, filler words, speaking duration, voice activity.

Audio → Librosa / PyAudioAnalysis → Communication Metrics
{
  "speechRate": 132, "pitchVariation": 0.64,
  "pauseDuration": 8.2, "fillerWords": 7, "speakingDuration": 47.5
}

POST /api/v1/analysis/audio

09

Video Analysis Service

Optional camera pipeline: OpenCV frame extraction → MediaPipe Face Mesh → facial landmarks → face presence, gaze direction, head pitch/yaw/roll, facial movement.

Boundary — this service must never output confidence %, emotion labels, or honesty scores. It is limited to observable behavioural indicators, not psychological inference.
10

Answer Evaluation Service

Answers "how good was the response?" — question, transcript, expected keywords, reference answer and job role feed a Llama 3 evaluator.

{
  "relevance": 82, "completeness": 75, "technicalCorrectness": 88,
  "keywordCoverage": 71, "grammar": 91, "conciseness": 84
}
11

Score Aggregation Service

Combines three independent sources into one final score.

POST /api/v1/scores/aggregate

12

16

Compute Layer

Note — a microservice is not the same as a Lambda function; either can run on FastAPI or Lambda.

Synchronous

API Gateway → FastAPI: Auth, Profile, Interview, Question, Report, Analytics

Asynchronous

S3 event → Lambda/Worker: Whisper → Audio → Video → Llama → Score → Report

17

Message Queue

Recommendation: add Amazon SQS — not yet in the SRS — so a submitted answer never runs its full AI pipeline inside one HTTP request.

18

API Gateway

The frontend never calls a service directly — every request is routed through one gateway, matching the SRS's existing route namespace.

/api/v1/auth/*       /api/v1/questions/*     /api/v1/reports/*
/api/v1/profile/*    /api/v1/analysis/*      /api/v1/analytics/*
/api/v1/interviews/* /api/v1/evaluation/*    /api/v1/admin/*

Implementation Roadmap

Phase 1Auth → Profile → Interview → Question Bank
Phase 2S3 Upload → SQS → Whisper → Audio Analysis
Phase 3Llama 3 → Answer Evaluation → Score Aggregation
Phase 4Report → Analytics → Admin
Phase 5Video Analysis → MediaPipe + OpenCV
Design principle — don't build a microservice for every minor function. Eight services give enough architectural depth for a capstone project without the overhead of deploying and debugging twelve-plus independent applications.
